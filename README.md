# MyRadius — backend

Backend API for **MyRadius**, a hyperlocal community app for Kenya: everything happening
around you — your neighbours, local sellers, services, groups, and events, all within
your radius.

Every user has their own radius, which adapts to how many active users are nearby: it
shrinks in dense areas so the feed stays genuinely local, and widens in quiet ones so
there is always something to see. Exact locations are never stored, shown, or logged.

The mobile clients (Flutter, Android and iOS) live in a separate repository. This service
is a modular monolith: FastAPI, PostgreSQL with PostGIS, Redis, and an arq worker.

## Requirements

- [Docker Desktop](https://docs.docker.com/desktop/) (Compose v2)
- [uv](https://docs.astral.sh/uv/) and Python 3.12, for running tests and tooling on the host

## Getting started

```bash
cp .env.example .env     # defaults match docker-compose.yml
docker compose up --build
```

That brings up four services:

| Service    | What it is                          | Address                 |
| ---------- | ----------------------------------- | ----------------------- |
| `api`      | FastAPI under Uvicorn, auto-reload  | http://localhost:8000   |
| `worker`   | arq background worker               | —                       |
| `postgres` | PostgreSQL 16 + PostGIS 3 + pg_trgm | `localhost:5432`        |
| `redis`    | Redis 7                             | `localhost:6379`        |

Then:

- API docs: <http://localhost:8000/docs>
- Liveness: <http://localhost:8000/health>
- Readiness, including database and Redis: <http://localhost:8000/ready>

The `api` container applies migrations on start, so the database is ready to use.

## Working on the code

```bash
uv sync                  # install dependencies into .venv
uv run ruff check .      # lint
uv run ruff format .     # format
uv run mypy app          # type-check
uv run pytest            # tests (needs postgres and redis up)
```

Tests run against a real PostGIS database rather than a stub, because the radius system
depends on PostGIS behaviour that no fake reproduces. `docker compose up postgres redis`
is enough to run them.

### Migrations

```bash
uv run alembic revision --autogenerate -m "describe the change"
uv run alembic upgrade head
uv run alembic downgrade -1
```

Review every autogenerated migration before committing it. Alembic does not always get
spatial indexes or enum changes right.

## Layout

```
app/
  main.py          application factory and router wiring
  core/            config, db, errors, logging, middleware, pagination, rate limiting
  modules/         one package per feature area: models, schemas, service, router
  workers/         arq settings and background tasks
migrations/        Alembic
tests/
docs/              ARCHITECTURE.md, DECISIONS.md, DATA_MAP.md
```

Routers stay thin and business logic lives in `service.py`. Modules call each other
through service functions, never through each other's routers.
